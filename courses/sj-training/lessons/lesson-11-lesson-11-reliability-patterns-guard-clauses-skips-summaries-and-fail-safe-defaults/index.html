Module

Module 04 - Robust Tool Engineering

Suggested Time

3 hours

What This Lesson Assumes

You already understand the introductory version of this topic from the previous course. This lesson focuses on applying that knowledge to a deployable, maintainable, AI-assisted pyRevit workflow.

Objectives

  • Replace fragile assumptions with explicit guard clauses.
  • Decide when a tool should stop, skip, or continue.
  • Build summary reporting into every production candidate.

Robust Tools Are Boring in a Good Way

A robust tool should not surprise users. It should clearly say what it did, what it skipped, and why.

Guard Clauses

Use guard clauses at the top of workflows:

if not selected_ids:
    forms.alert('Select at least one element before running this tool.', exitscript=True)

Stop, Skip, Continue

Stop

Use when the tool cannot safely proceed.

Skip

Use when one item is invalid but the rest can continue.

Continue with Warning

Use when output may be incomplete but still useful.

Standard Summary

Every production tool should report:

Processed: 24
Skipped: 3
Warnings: 2
Errors: 0
Model changed: Yes / No

Exercise

Add the standard summary pattern to your Phase 1 milestone tool.
